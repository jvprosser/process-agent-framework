### Phase 8: Cloudera AI UI Test Harness & Debug Viewer

**To: Grok (Cursor)**
**From: Implementation Architect**

The backend is fully verified. We are now beginning the frontend implementation. The target deployment environment is a Cloudera AI Application (formerly CML).

For this first UI phase, you will build a diagnostic testing harness. It must present a split-pane interface: a natural language chat on the left, and a raw debug/JSON viewer on the right to inspect the strict UI envelope and any intermediate Chain-of-Thought (CoT) from the Mistral model.

**Context Updates:**

* Target directory: `src/ui/` (for frontend assets) and `src/main.py` (for serving).
* Cloudera AI Applications require web servers to bind to the port specified by the `CDSW_APP_PORT` environment variable (defaulting to `8080` for local dev) and the host `127.0.0.1`.
* To avoid CORS and multi-process management inside the Cloudera container, the FastAPI app will serve this test harness directly as static HTML/JS/CSS.

#### Task 1: Update FastAPI for Cloudera AI and Static Serving

Modify `src/main.py`.

* Import `StaticFiles` from `fastapi.staticfiles`.
* Mount the `src/ui` directory to serve the frontend at the root (`/`).
* Update the `uvicorn.run` block to dynamically read the host and port:
```python
import os
port = int(os.getenv("CDSW_APP_PORT", 8080))
uvicorn.run(app, host="127.0.0.1", port=port)

```



#### Task 2: Capture LLM Chain-of-Thought (CoT)

Modify `src/api/chat.py` and `src/core/agent_loop.py`.

* The Mistral SDK captures tool-call iterations and reasoning steps in the message history before yielding the final text response.
* In `run_specialist` and `run_intake`, extract the raw message logs (or tool-call names/arguments) generated by the Mistral client during the run.
* Update the API response schema in `src/api/chat.py` to include a new array inside the `meta` node: `meta.debug_cot: list[str]`. Map the captured tool execution logs and intermediate LLM reasoning into this array so the UI can display them.

#### Task 3: Build the Split-Pane UI Harness

Create `src/ui/index.html`, `src/ui/style.css`, and `src/ui/app.js`. Do not use a heavy build system (like Webpack or Vite) for this harness; write clean, vanilla ES6 modules or a standalone React CDN script.

* **Layout (`style.css`):** Implement a strict 50/50 CSS Grid or Flexbox layout taking up `100vh`. Disable global scrolling; each pane must scroll independently.
* **Left Pane (Chat):**
* A drop-down to select the active `pack_id` (`claims`, `underwriting`, etc.).
* A scrollable chat history displaying user messages and the agent's final `content.chat_text`.
* An input text field and submit button for the natural language prompt.


* **Right Pane (Debug/JSON Viewer):**
* A dark-themed `<pre><code>` block.
* Upon receiving the POST response from `/api/v1/chat`, immediately `JSON.stringify(response, null, 2)` and inject it here.
* Ensure the `meta.debug_cot` array and the `layout.widgets` directives are clearly visible for backend inspection.



**Phase 8 Acceptance Criteria:**

1. Running `python src/main.py` binds the server to `127.0.0.1:$CDSW_APP_PORT`.
2. Accessing `[http://127.0.0.1:8080/](http://127.0.0.1:8080/)` loads the split-pane UI.
3. Submitting a prompt in the left pane displays the LLM's final text in the chat window, while the right pane simultaneously populates with the fully pretty-printed JSON envelope, including the `debug_cot` intermediate execution logs.
