### Phase 2: Agent Orchestration and Specialist Factory

**To: Grok (Cursor)**
**From: Implementation Architect**

The rules of engagement remain in force. Phase 1 is complete: the `PackManager`, local Mistral client, and core `@tool` wrappers are verified.

In this phase, you will build the Mistral agent execution loop. Do not build the FastAPI HTTP endpoint yet. Your objective is to orchestrate the handoffs between the natural language Orchestrator, the Intake pipeline, and the dynamic Specialist Agent.

**Context Updates:**

* Target file: `src/core/agent_loop.py`
* The Orchestrator acts as the "front door" for the user.
* The Intake Agent is responsible for executing the setup tools.
* The Specialist Agent executes the final action based strictly on the playbook's output.

#### Task 1: The Orchestrator (Front Door)

Implement a Python function or class `run_orchestrator(user_text: str, client: Mistral) -> str`.

* Use the local Mistral client to evaluate the unstructured `user_text` (e.g., "Please process claim 401" or "What's the status of FNOL 88?").
* The Orchestrator's sole job is to extract the **entity ID** (e.g., "401", "88", "9100").
* **Constraint:** Use Mistral structured output or a strict system prompt to ensure it returns only the extracted ID, without conversational padding. If no ID is found, return `None`.

#### Task 2: The Intake Execution Pipeline

Implement `run_intake(entity_id: str, client: Mistral, pack: PackManager) -> dict`.

* This step bridges the Orchestrator to the deterministic rules engine.
* Provide the Intake Agent with the `build_session_graph` and `evaluate_playbook` tools.
* Force or prompt the Intake Agent to invoke `build_session_graph` with the `entity_id`, followed immediately by `evaluate_playbook`.
* Return the resulting routing JSON (which must contain `next_step`, `agent_role`, `allowed_tools`, and `write`).
* **Constraint:** The LLM must not alter the output of `evaluate_playbook`. It must pass the JSON block back exactly as generated by the CEL execution.

#### Task 3: The Specialist Agent Factory

Implement `run_specialist(route_json: dict, client: Mistral, pack: PackManager) -> dict`.

* Dynamically construct a Specialist Agent based on the `agent_role` defined in the `route_json`.
* Fetch the specific system prompt for this agent from the active pack's `agents/` directory (e.g., `packs/<pack>/agents/<agent_role>.md`).
* Bind **only** the tools listed in the `route_json`'s `allowed_tools` array (which will typically include `run_named_write` or `run_named_query`).
* Pass the routing JSON summary to the Specialist Agent and instruct it to execute the required `write` label and draft the final conversational response.
* Return an object containing the Specialist's final text and the `route_json` (to be used in Phase 3 for the UI envelope).
